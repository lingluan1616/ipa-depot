# IPA Depot：决策与计划（2026-10-26）

## 背景
- Pastel（EEliberto/Pastel-macOS 20260929.2）的下载链路已被 Apple 10 月的接口变更废掉：下载请求需要 kbsync 设备授权，Pastel 没有实现；作者表示无法修复。本机已用废纸篓方式清除 Pastel。
- majd/ipatool v2.7.0（2026-10-09，MIT）实现了 ent/download + kbsync 通道，本机实测可登录并下载（谜底黑胶 3.8.5，155.6 MB，中途断线 4 次靠续传完成）。
- 用户不用终端，需要一个 macOS 图形化软件，做好后发布到用户自己的 GitHub 公开仓库。
- 现成开源方案调研见 `00-调研-现有方案与集成要点.md`：没有同时满足「macOS 原生 GUI + 走 kbsync 通道 + 历史版本 + 有许可证可再发布」的项目；最接近的 a23bc/ipatool-gui 是 Electron（107 MB）。

## 工程决策（主会话定，依据调研报告）
1. **锁定 ipatool v2.7.0**，二进制放 `vendor/ipatool/`（universal），构建时拷进 `Contents/Resources/bin/ipatool`；附 `vendor/ipatool/LICENSE`。不打包 unicorn 与 Apple 组件，让 ipatool 运行时自己下载到 `~/Library/Caches/ipatool`。
2. **关闭沙盒**，不开 Hardened Runtime（避免 ad-hoc 下 dlopen unicorn 被拦）。
3. **登录走伪终端（PTY）**，密码绝不进命令行参数；2FA 按「检测提示 → 弹输入框 → 回填」处理。
4. **不覆盖子进程 HOME**（否则登录钥匙串找不到）；设置 `XDG_STATE_HOME` 指向 `~/Library/Application Support/IPA Depot/state`；若 `~/.ipatool` 已存在则 ipatool 会沿用它，文档注明。
5. **钥匙串**：ipatool 凭据存登录钥匙串 `ipatool-auth.service`，首次运行系统会弹「始终允许」，界面要预先提示。第一版只做单账号。
6. **进度**：用交互模式解析进度条文本，`.tmp` 文件大小轮询兜底；暂停 = 杀子进程，继续 = 同参数重跑（ipatool 自动续传）。
7. **历史版本**：`list-versions` 取 ID 列表，`get-version-metadata` 逐个取版本号与日期，并发 ≤3、磁盘缓存、懒加载。
8. **更新检查**：第一版只调 GitHub Releases API 提示新版，不接 Sparkle。
9. **错误文案**：按 ipatool 已知错误字符串映射成中文（license is required / password token is expired / account is disabled / 2FA 等），并提示大陆网络对 Apple 下载域名的连通性问题。
10. **字体与视觉**：macOS 原生控件；**标题、App 名、版本号与各类数字用阿里妈妈数黑体 Bold**（用户 2026-10-26 定），正文与控件用系统字体；字体文件随 App 打包并附官方许可文件。

## 阶段划分
- **阶段一（引擎）**：仓库骨架、xcodegen 工程、ipatool 拉取与 universal 合并脚本、Core 引擎（进程封装、JSON 行解析、PTY 登录、搜索、版本、下载与进度、错误映射）、单元测试、真机冒烟。
- **阶段二（界面）**：SwiftUI 界面：登录页、搜索页、App 详情与版本列表、下载队列与进度、下载记录、设置（下载目录、清理缓存）。
- **阶段三（打包）**：Release 构建脚本、ad-hoc 签名、zip/dmg、README（含打开方式）、CHANGELOG、GitHub Actions 可选。
- **验收**：主会话按磁盘实物与实测验收；用户亲自试用；通过后再建仓库推送与发 Release。

## 红线（所有子代理）
- 不执行 `ipatool auth login / purchase / auth revoke`；真实登录与下载只由主会话或用户操作。
- 不改动、不删除钥匙串条目；不碰 `~/.ipatool`、`~/Library/Caches/ipatool` 以外的用户数据；不删除任何仓库外文件。
- 临时文件只放在仓库 `build/` 或系统 TemporaryDirectory，收工前自清。
- 不 push、不建远程仓库；本地 git 提交允许。

## 阶段五：多账号与地区切换（用户 2026-10-30 提出）
**需求**：用户有多个地区的 Apple ID，要在 App 里保存多个账号，随时切换地区搜索与下载。
**用户拍板**：各账号密码存入 macOS 钥匙串（IPA Depot 自己的条目），切换时自动重登，一键完成。

**底层约束（来自 docs/00 调研 2.6/3.2 节）**：ipatool 在 macOS 只有一个钥匙串账号槽位（`ipatool-auth.service`/`account`）；kbsync 缓存在 `kbsync-v1`；Cookie 在状态目录（`~/.ipatool` 已存在时优先它，否则 `XDG_STATE_HOME/ipatool`）。因此多账号只能由 App 管理：切换 = 保存当前账号 Cookie → `auth revoke` → 换入目标账号 Cookie → 用存储的密码经 PTY `auth login`（必要时 2FA）。

**主会话定的设计**：
1. 账号列表 `accounts.json`（App Support）：id、邮箱、显示名、地区标签（用户添加时从列表选：中国大陆/香港/台湾/日本/美国/韩国/其他，可改）、最近登录时间、当前激活。密码存钥匙串，service `app.ipadepot.mac.accounts`，account=邮箱；由 App 自己创建的条目读取不弹窗（换二进制后可能再弹一次，文档注明）。
2. 每账号独立 Cookie：`App Support/accounts/<id>/cookies`；切换前后在 ipatool 实际状态目录与该目录间拷贝。实现前须在 ipatool v2.7.0 源码核实 `auth revoke` 是否删除 cookies、`auth login` 是否重写 cookies，并据此确定拷贝时机。
3. 侧栏底部改为账号切换菜单：地区标签 + 邮箱，列出全部账号，含「添加账号」「管理账号…」；切换时全屏轻量遮罩显示进度，可能弹 2FA 输入。
4. 搜索/历史版本在切换后自动重新查询；版本缓存键改为 `appID + 账号 id`。
5. 下载队列任务绑定账号：开始一个不属于当前账号的任务时先自动切换（界面提示），再下载；记录页显示账号地区标签。
6. 升级迁移：已有单账号用户首次启动 0.2.0 时，若 `auth info` 成功且账号表为空，自动建一条账号（邮箱来自 auth info，地区标签让用户选一次，密码标记「待补」，切走再切回时补一次即可）。
7. 版本号升到 0.2.0；README 加「多账号与地区」一节；CHANGELOG 0.2.0。
**红线不变**：子代理不得执行真实 ipatool 的 login/revoke/purchase/download，不碰钥匙串真实条目与 `~/.ipatool`；真实切换由用户验收。

## 阶段六：地区浏览 + 发布前小修（用户 2026-10-30 定，随 0.2.0 首发）
**背景**：用户的外区账号唯一受信任设备是 Apple Watch，ipatool 通道的 2FA 只会把码推到受信任设备、没有「改发短信」入口（Apple 网页登录才有）。主会话判定：在 App 内做短信验证 = 重新实现 Apple 私有登录协议，**不做**。替代：像 Pastel 那样提供「浏览地区」，但把下载也接上账号匹配。
**设计**：
1. 搜索页加「浏览地区」选择：默认「跟随当前账号」；可选 中国大陆 cn / 香港 hk / 台湾 tw / 日本 jp / 美国 us / 韩国 kr / 其他（自填两位代码）。非跟随时用 Apple 公开的 iTunes Search API（`https://itunes.apple.com/search?term=…&country=<cc>&entity=software|iPadSoftware|macSoftware&limit=…`）搜索，结果映射到现有 `AppSummary`（trackId / bundleId / trackName / version / price / artworkUrl100 / sellerName / supportedDevices→平台），标注「公开目录」。选择持久化。
2. 从公开目录结果进入历史版本或下载时，需要一个地区标签与浏览地区匹配的账号：当前账号匹配 → 直接用；其他账号匹配 → 走现有自动切换；都不匹配 → 提示「没有 X 地区的账号」并提供「添加账号」（地区预选）。地区标签与国家代码的映射放在一个 `RegionCatalog`。
3. 阶段五遗留小修一并做：② 启动时 `auth info` 的邮箱不在账号表 → 自动加入并询问地区；③ 迁移时给旧记录与队列条目盖上迁移账号 id；2FA 输入页文案改为「验证码已推送到该 Apple ID 的所有受信任设备（含 Apple Watch），请在设备通知中查看；此通道不支持短信验证」；README 常见问题补：验证码去向与 Apple Watch 情况、`~/.ipatool` 迁移行为、浏览地区与账号地区的关系。

## 阶段八：下载按钮反馈与重复任务去重（用户 2026-10-31 提出，随 0.2.0 首发）
**问题**：搜索结果行点「下载最新版」没有任何反馈；连点多次会加出多个同一 App 的任务（文件名自动加序号，所以都能排进去）。
**主会话定的设计**：
1. **队列去重（根治）**：`DownloadQueue.add` 先查是否已有「未结束」的同任务——键 = appID + externalVersionID（nil 即最新版）+ platform + accountID（nil 视为当前账号）；状态属于排队 / 切换账号 / 下载中 / 已暂停的算未结束，已完成 / 失败 / 取消的不算。命中则不新建，返回已有任务 id（对外区分「新建 / 已存在」）。历史版本页、公开目录自动切换路径、「领取免费许可并下载」全部走同一入口，自然去重。
2. **按钮即时反馈**：搜索结果行与历史版本页的下载按钮三态：默认「下载最新版」/「下载」；点击后立刻变为带勾的「已加入」（约 1.5 秒）；只要队列里存在匹配的未结束任务，就显示「已在队列」且禁用；任务结束（完成 / 失败 / 取消）后恢复默认可再次下载。匹配状态由视图模型从队列的 items 流实时推导，不靠点击记忆，所以重开搜索页也正确。
3. 公开目录结果需要先匹配 / 切换账号时，按钮在解析期间显示小菊花并禁用，避免这段无反馈的空窗再被连点。
