# ipatool 图形化：现成方案盘点与自研集成要点

- 调研日期：2026-10-26（北京时间凌晨）
- 调研方式：GitHub REST API / raw 源码 / WebFetch / WebSearch / 本机 `ipatool <子命令> --help` 与只读命令
- 本机已执行的 ipatool 命令（均为只读）：`--version`、各子命令 `--help`、`download`（不带参数，用于拿错误 JSON 格式）、`search telegram --limit 2 --format json`、`auth info --format json`（输出里的姓名/邮箱已打码）。**没有**执行 login / download（带参数）/ purchase / revoke / list-versions。
- 本机没有下载或安装任何东西。

---

## 一句话结论

1. **没有一个现成项目同时满足**：「macOS GUI + 走 ipatool ≥2.7.0 的 kbsync 通道 + 能搜任意 App + 能下历史版本 + 有开源许可证可二次发布 + 装起来不需要终端」。
2. **最接近、能直接装来自用的**是 **a23bc/ipatool-gui**（Electron，MIT，首次启动自动从官方 Release 下载 ipatool 并校验 SHA-256，支持历史版本、下载队列、多账号）。缺点：mac 包 107 MB；ad-hoc 签名、未公证，按它 README 的说法首次打开会报「已损坏」，要用 `xattr` 去隔离属性（主会话可以替用户在本机执行）。
3. **Asspp / AssppWeb 不走 kbsync 通道**：它们的底层库 ApplePackage 官方文档写明“还没实现 ent/download 和 kbsync”，作者 10-25 关闭了加 kbsync 的 PR，理由是“不接受二进制模拟”。
4. **自己做是可行的**，路线是 SwiftUI 壳 + 内置官方 Release 版 ipatool 子进程 + `--format json` 解析。必须处理的硬问题有 5 个：关沙盒；钥匙串“始终允许”弹窗（每次换 ipatool 二进制都会再弹）；下载进度只能从进度条文本里抠，或者轮询 `.tmp` 文件大小；2FA 两段式登录；没有 Developer ID（99 美元/年）就没法公证，别人从 GitHub 下载后要手动“仍要打开”。

### 1.1 Asspp 系为什么不走 kbsync（关键证据）

- ApplePackage 官方文档 [SAPIntegration.md](https://github.com/Lakr233/ApplePackage/blob/main/SAPIntegration.md)（2026-10-20 版）原文：“ApplePackage does not yet implement the preferred `ent/download` path and its separate `kbsync` blob.” 它的下载恢复顺序是 `volumeStoreDownloadProduct → redownloadProduct → updateProduct`。
- AssppWeb [PR #98](https://github.com/Lakr233/AssppWeb/pull/98)《download through ent/download with browser-generated kbsync》在 2026-10-25 被关闭、没有合并。维护者 Lakr233 的评论：“implement the algorithm your self or we do not accept binary emulation in Asspp products.”
- Asspp 4.2.2 的 release 说明（2026-10-20）写的是“macOS ZIP without a personal development team”，没有提到公证。

### 1.2 判定汇总

- **用户想马上自用**：装 **a23bc/ipatool-gui v0.2.0**（mac-arm64）。它会优先用本机 Homebrew 的 ipatool 2.7.0，并自带历史版本、队列和多账号。主会话需要替用户做两件事：解压后执行一次 `xattr -dr com.apple.quarantine`；首次运行时提醒用户在钥匙串弹窗里点“始终允许”。
- **要做“自己的、发布到 GitHub 的”软件**：没有能直接改名发布的现成品。a23bc（MIT）的设计可以直接借鉴，见第 3 节。AppDowngrader、xKleja、ipatoolUI 都没有 LICENSE 文件，**代码不能拿来二次分发**。

## 2. ipatool v2.7.0 本身的可集成性

### 2.1 许可证与再分发

- 许可证：**MIT**（[LICENSE](https://github.com/majd/ipatool/blob/v2.7.0/LICENSE)，Copyright (c) 2021 Majd Alfhaily）。本机 `brew info ipatool` 也显示 `License: MIT`。
- 再分发要求：MIT 只要求在副本里保留版权声明和许可声明。做法是把 LICENSE 原文放进 App 包（比如 `Contents/Resources/ipatool-LICENSE`），并在“关于”页面注明来源。
- ipatool 运行时会下载两类第三方组件，GUI **不应该**把它们打包进安装包：
  - unicorn 动态库：来自 PyPI wheel，unicorn 本身是 GPLv2。这一条许可证信息是常识，本次没有去核对 unicorn 仓库原文，见核实状态栏。
  - Apple 私有框架文件：来自 Apple 的 OSXUpd10.9.pkg。
  只要让 ipatool 运行时自己去下载，就不涉及我们再分发这些文件。

### 2.2 版本现状（重要）

- 最新 Release 是 **v2.7.0，发布于 2026-10-09**，资产包括 `ipatool-2.7.0-macos-arm64.tar.gz`、`macos-amd64.tar.gz`（各附 `.sha256sum`）、windows/linux/ios（GitHub API）。
- **main 分支在 2.7.0 之后已经合入、但还没发布的修复**（GitHub API commits）：
  - 2026-10-15 `fix: accept legacy ios packages without platform declarations`：修 [#618](https://github.com/majd/ipatool/issues/618)，2.7.0 下载老 App 会报 `failed to validate package platform: downloaded package does not declare iPhoneOS support`。**这条直接影响“下载历史版本”**。
  - 2026-10-15 `fix: allow redownloads for delisted ios apps`
  - 2026-10-18 `feat: use apple frameworks for store operations`（5dc4c80，104 个文件，+68,664 行），2026-10-11 `feat: migrate sap services to macos 27`。main 上还有 [#634](https://github.com/majd/ipatool/issues/634)：“[main] auth login panics in the store emulator…”
  - 结论：**GUI 要锁定一个具体的 ipatool 版本**，JSON 解析要能容忍字段变化；下一版 ipatool 的内部改动很大。
- 2.7.0 的已知问题：[#631](https://github.com/majd/ipatool/issues/631)（2026-10-21 提交，未修）。慢机器上生成 kbsync 会超过 1 分钟的硬上限，于是回退到旧下载通道，结果每次下载都要多等约 60 秒。同一 issue 里 M4 Pro 生成 kbsync 只要 4.4 秒，缓存后约 3 秒。

### 2.4 `--format json` 输出结构

所有 JSON 输出都是 zerolog 产生的**每行一个 JSON 对象**，**全部写到 stdout**（包括错误，见 [cmd/common.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/common.go) 里的 `zerolog.SyncWriter(os.Stdout)`）。每行都带 `level` 和 `time`。失败时进程退出码为 1（[cmd/root.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/root.go)）。

| 命令 | 成功时的行（字段） | 依据 |
|---|---|---|
| 任意命令失败 | `{"level":"error","error":"<信息>","success":false,"time":…}`，exit=1 | **本机实测**：`ipatool download --format json --non-interactive` 输出 `{"level":"error","error":"either the app ID or the bundle identifier must be specified","success":false,"time":"2026-10-26T03:26:57+08:00"}`，exit=1 |
| `search` | `{"level":"info","count":N,"apps":[{"id","bundleID","name","version","price","platforms":[…]}],"time"}` | **本机实测**：`{"level":"info","count":1,"apps":[{"id":333903271,"bundleID":"com.atebits.Tweetie2","name":"X（前身为Twitter）","version":"12.37","price":0,"platforms":["iphone","ipad"]}],…}`（注意：搜索走账号所在的商店地区，本账号是中国区，搜 telegram 返回的是 X） |
| `auth info` | `{"level":"info","name","email","success":true,"time"}` | 本机实测（已打码） |
| `auth login` | 先输出一行 `{"level":"info","message":"preparing authentication; the first login may take a few minutes"}`；成功时 `{"name","email","success":true}`；**需要 2FA 且是 --non-interactive 时**输出 `{"level":"info","message":"2FA code is required; run the command again and supply a code using the `--auth-code` flag"}`，**退出码为 0，而且没有 success 字段** | [cmd/auth.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/auth.go) |
| `list-versions` | `{"externalVersionIdentifiers":["…",…],"bundleID":"…","success":true}`。CLI **不输出**最新版本 ID，也不输出可读版本号 | [cmd/list_versions.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/list_versions.go) |
| `get-version-metadata` | `{"externalVersionID","displayVersion","releaseDate"(RFC3339),"success":true}` | [cmd/get_version_metadata.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/get_version_metadata.go) |
| `download` | `{"output":"/绝对路径/xxx.ipa","purchased":bool,"success":true}` | [cmd/download.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/download.go) |
| `purchase` / `list-purchases` | 与 search 同风格（apps 数组带 `purchaseDate`） | 源码 |

常见错误字符串（适合 GUI 用来做文案映射，见 [pkg/appstore](https://github.com/majd/ipatool/tree/v2.7.0/pkg/appstore)）：`auth code is required`、`2FA code must contain exactly six digits`、`password token is expired`、`license is required`、`license already exists`、`app not found`、`account is disabled`、`apple did not complete verification; try a fresh 2FA code`。

**进度输出**：
- 进度条只在**交互模式**（不带 `--non-interactive`）下创建，写到 stdout，**不检查是不是 TTY**（[cmd/download.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/download.go)：`if interactive { progress = progressbar.NewOptions64(…, OptionSetWriter(os.Stdout) …) }`）。带 `--non-interactive` 时**完全没有进度**。
- JSON 里没有进度事件。
- 文件先写到 `<目标>.tmp`，用 `Range: bytes=<已有大小>-` 续传，完成后再改名（[appstore_download.go](https://github.com/majd/ipatool/blob/v2.7.0/pkg/appstore/appstore_download.go) 第 117、236–322 行）。
- 所以 GUI 拿进度只有两条路：① 交互模式下解析进度条文本，格式形如 `downloading  21% [======>  ] (12/45 MB, 1.2 MB/s)`，1000 进制（来自 a23bc 的 [architecture.md](https://github.com/a23bc/ipatool-gui/blob/main/docs/architecture.md)）；② 轮询 `.tmp` 文件大小。“暂停”就是杀掉子进程，“继续”就是用同样的参数重跑。
- 默认文件名是 `<bundleID>_<appID>_<version>.ipa`（macOS 应用是 `.pkg`）。不传 `-o` 时落在进程的工作目录。

### 2.5 MCP 模式

- 启动：`ipatool mcp`，走 stdio JSON-RPC。日志改写到 stderr。强制非交互。**不提供登录工具**，要先在外面执行 `ipatool auth login`（[cmd/mcp.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/mcp.go)，README main 分支 “MCP tools” 一节）。
- 提供 6 个工具（[cmd/mcp_tools.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/mcp_tools.go)）：

| 工具 | 只读 | 输入 | 输出要点 |
|---|---|---|---|
| `search_apps` | 是 | term, limit?, platform? | term/limit/platform/count/apps[]（trackId, bundleId, trackName, version, price, purchaseDate, platforms） |
| `download_app` | 否 | app_id / bundle_identifier, platform?, output?, external_version_id?, purchase?（只能拿免费授权） | output, purchased, success |
| `list_app_versions` | 是 | app_id / bundle_identifier, platform? | externalVersionIdentifiers[], **latestExternalVersionID**（CLI 没有这个字段）, bundleID |
| `get_version_metadata` | 是 | 同上 + external_version_id | displayVersion, releaseDate |
| `list_purchases` | 是 | page?, max_results?（1–100）, platform? | count, totalCount, page, apps[] |
| `purchase_app` | 否 | app_id / bundle_identifier | alreadyOwned, success（只支持免费 App） |

- 限制：所有工具调用经过一个容量为 1 的 gate，**同一时间只跑一个**；`download_app` 不传进度（Progress=nil）。
- 结论：MCP 可以当 GUI 的“常驻后端”来做搜索、版本列表、元数据，省掉每次冷启动进程。但登录和带进度的下载仍然要走 CLI。

### 2.6 会话存在哪里、`--keychain-passphrase` 的作用

- **状态目录**：默认 `~/.ipatool/`，里面放 `cookies`。如果设了**绝对路径**的 `XDG_STATE_HOME`（其次 `XDG_DATA_HOME`），就改用 `<它>/ipatool`；但只要 `~/.ipatool` 已经存在，就优先用旧目录（[cmd/state_directory.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/state_directory.go)）。本机 `~/.ipatool/` 里目前只有 `cookies`（5356 字节）。
- **账号凭据**：存在 **macOS 登录钥匙串**，服务名 `ipatool-auth.service`，键名 `account`（[cmd/constants.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/constants.go)）。本机 `security find-generic-password -s ipatool-auth.service` 确认条目在 `~/Library/Keychains/login.keychain-db`。条目内容是整个 `Account` 结构体，**包括 Apple ID 明文密码**（字段 `Password`），用于 token 过期后自动重新登录（[account.go](https://github.com/majd/ipatool/blob/v2.7.0/pkg/appstore/account.go)、appstore_login.go 第 214/223 行）。kbsync 缓存也放在钥匙串里，键名 `kbsync-v1`（[appstore_kbsync_cache.go](https://github.com/majd/ipatool/blob/v2.7.0/pkg/appstore/appstore_kbsync_cache.go)）。
- **后端选择**：允许的后端依次是 `[keychain, secret-service, file]`。macOS 版（CGO 编译）的 keychain 后端排第一，总能打开（[byteness/keyring v1.9.0](https://github.com/byteness/keyring/blob/v1.9.0/keychain_macos.go)，build tag `darwin && !ios && cgo`）。
- **`--keychain-passphrase` 只对 `file` 后端生效**，用来解锁加密的凭据文件（[cmd/common.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/common.go) 里的 `FilePasswordFunc`）。**在 macOS 上实际用不到**，因为根本不会落到 file 后端；在 Linux/Windows 非交互运行时它才是必填。a23bc 的 architecture.md 也写了同样的结论：“macOS…共用登录钥匙串里的同一条记录，没有任何 flag / 环境变量 / 配置文件能改变这一点。”

### 2.7 下载历史版本的命令链

1. `ipatool list-versions -b <bundleID>（或 -i <appID>） --format json --non-interactive` → `externalVersionIdentifiers[]`。这一步内部发的是 download-product 请求，**账号没有该 App 的授权时会报 `license is required`**（[appstore_list_versions.go](https://github.com/majd/ipatool/blob/v2.7.0/pkg/appstore/appstore_list_versions.go)）。免费 App 先执行 `purchase`，付费 App 必须先在 App Store 里买过。
2. 对每个 ID 执行 `ipatool get-version-metadata -b … --external-version-id <id> --format json` → `displayVersion`、`releaseDate`。每个 ID 一次调用，GUI 要做限并发、懒加载和缓存。
3. `ipatool download -b … --external-version-id <id> -o <目录>`。不带 `--non-interactive` 才有进度条，带 `--purchase` 会在缺授权时自动领取免费授权。
4. 2.7.0 下载很老的版本会碰到 #618 的平台校验报错，修复只在 main 分支（见 2.2）。

### 2.8 kbsync 首次生成的依赖（源码 + 本机缓存实测）

- **触发**：`download` 首选 `ent/download` 接口（`/WebObjects/DownloadDispatch.woa/wa/ent/download`），它需要 kbsync blob。生成成功后存进钥匙串 `kbsync-v1`；之后先用缓存，被拒一次就重新生成（[appstore_kbsync.go](https://github.com/majd/ipatool/blob/v2.7.0/pkg/appstore/appstore_kbsync.go)）。整个流程有 2 分钟超时，模拟器单次调用上限 1 分钟。超时就回退到旧通道（#631）。
- **依赖 1：unicorn 2.1.4 动态库**（[internal/sap/unicorn/artifact.go](https://github.com/majd/ipatool/blob/v2.7.0/internal/sap/unicorn/artifact.go)、[cache_runtime.go](https://github.com/majd/ipatool/blob/v2.7.0/internal/sap/unicorn/cache_runtime.go)、[library_unix.go](https://github.com/majd/ipatool/blob/v2.7.0/internal/sap/unicorn/library_unix.go)）
  - 来源：`files.pythonhosted.org` 上的 `unicorn-2.1.4-cp37-abi3-macosx_11_0_arm64.whl`。PyPI API 显示 12,142,730 字节；x86_64 版 12,958,220 字节。下载后同时校验 wheel 和 dylib 的 SHA-256。
  - 解压到 `os.UserCacheDir()/ipatool/unicorn/2.1.4/<sha256>/libunicorn.2.dylib`，即 `~/Library/Caches/ipatool/unicorn/2.1.4/7207c8e3…/libunicorn.2.dylib`。**本机实测 16,232,448 字节，签名为 adhoc,linker-signed**。
  - 加载方式：purego `Dlopen(RTLD_NOW|RTLD_LOCAL)` 按绝对路径加载，**不靠 DYLD 搜索路径，也不需要和 ipatool 放在一起**。
  - 本机还残留一个下载中断留下的 `.unicorn-artifact-890872054`（2,366,530 字节，2026-10-25 20:35）。GUI 可以考虑提供“清理缓存”按钮。
- **依赖 2：Apple 组件**（[internal/sap/assets/assets.go](https://github.com/majd/ipatool/blob/v2.7.0/internal/sap/assets/assets.go)、[storeagent.go](https://github.com/majd/ipatool/blob/v2.7.0/internal/sap/assets/storeagent.go)）
  - 来源：`swcdn.apple.com/.../OSXUpd10.9.pkg`。HEAD 实测 Content-Length 1,276,165,185，支持 `accept-ranges: bytes`。ipatool 用 HTTP Range 打开 xar 包，从 Payload 内偏移 0x352F40D5 开始流式 bzip2 解压，直到取齐所需文件，**不会下载整个 1.28 GB**。实际流量本次没有测。
  - 缓存位置：`~/Library/Caches/ipatool/sap/apple-assets-v2/`，有 CommerceKit 3,271,840、CommerceCore 207,744、CoreFP 29,014,912、CoreFP.icxs 5,288,352 字节，合计约 36 MB；`~/Library/Caches/ipatool/sap/apple-storeagent-v1/storeagent` 2,580,176 字节。本机实测与源码里写死的大小完全一致。
  - 本机 `~/Library/Caches/ipatool` 合计 **56 MB**（sap 39 MB + unicorn 18 MB）。
- **对 GUI 的影响**：首次登录或首次下载要访问 `files.pythonhosted.org` 和 `swcdn.apple.com`，login 会先打一行“first login may take a few minutes”。GUI 要显示“首次准备组件”这类不确定进度的状态。在中国大陆网络下，这两个域名和 `p*-buy.itunes.apple.com` 的连通性要纳入错误提示（a23bc README 的 “Network tip” 原文为 “On some networks, Apple purchase/download endpoints (e.g. `p47-buy.itunes.apple.com`) are not directly reachable”）。

## 3. 自己做 GUI 的工程要点（SwiftUI 壳 + 内置 ipatool）

### 3.1 沙盒：必须关闭

- 原因 1（源码）：ipatool 要往 `~/.ipatool`、`~/Library/Caches/ipatool` 写文件，要从网上下载 dylib 后 `dlopen`，还要读写登录钥匙串里的旧式 ACL 条目。沙盒里子进程会继承沙盒，HOME 会被重定向到容器目录，于是和用户已有的 `~/.ipatool` 会话分开，而且下载回来的 dylib 也加载不了。
- 原因 2：本来就不走 Mac App Store。上架需要沙盒，但这类工具过不了审核。所有调研到的 macOS 同类项目，比如 AppDowngrader 的 entitlements，都只有 `allow-jit` 和 `disable-library-validation`，**没有 `com.apple.security.app-sandbox`**（[AppDowngrader.entitlements](https://github.com/rxliuli/AppDowngrader/blob/main/AppDowngrader.entitlements)）。
- 判定：**关沙盒**，只通过 GitHub 分发。

### 3.2 钥匙串弹窗：会弹，每换一个 ipatool 二进制就再弹一次

- 机制：keyring 写条目时 `TrustedApplications: nil`（[keychain_macos.go](https://github.com/byteness/keyring/blob/v1.9.0/keychain_macos.go) 第 208–222 行），go-keychain 把 nil 转成 `SecAccessCreate` 的 NULL（[go-keychain macos.go](https://github.com/byteness/go-keychain/blob/main/macos.go) `createAccess`）。Apple 官方文档 [SecAccessCreate](https://developer.apple.com/documentation/security/secaccesscreate(_:_:_:)) 原文：“Use nil to trust only the calling app.” 也就是说，**只有当初创建条目的那个 ipatool 二进制被信任**。
- 用户现在的条目是 Homebrew 的 `/opt/homebrew/Cellar/ipatool/2.7.0/bin/ipatool` 创建的。GUI 内置另一份二进制，读取时系统会弹窗，要求输入**Mac 登录密码**，点“始终允许”。ad-hoc 签名的二进制没有稳定的签名身份，**以后升级 ipatool 还会再弹**。第三方佐证：AppDowngrader README 的 “First Run: macOS Keychain Prompt” 一节原样描述了这个弹窗；IPArchive README 写“macOS ties Keychain item access to the signing identity… signature changes on every rebuild”。
- 另一种已知报错：系统弹出 “Keychain Not Found / A keychain cannot be found to store "account"”，原因是用户没有默认钥匙串（[a23bc #25](https://github.com/a23bc/ipatool-gui/issues/25)，2026-10-20）。GUI 要能识别这种情况并给出指引。
- 多账号：macOS 上**只有一个共享槽位**，切账号时只能由 GUI 替用户保存和回写这条记录（a23bc 用 `/usr/bin/security` + safeStorage 实现）。第一版建议**只做单账号**。

### 3.3 Homebrew 版与 Release 版二进制的差异

| | Homebrew 2.7.0（本机） | 官方 Release 2.7.0 |
|---|---|---|
| 构建 | Homebrew bottle，在 macOS 27.0 / Xcode 27.0 上 `CGO_ENABLED=1 go build`（本机 INSTALL_RECEIPT.json、formula） | GitHub Actions macos-latest，`CGO_ENABLED=1`，`CGO_CFLAGS/LDFLAGS=-mmacosx-version-min=10.15`（[release.yml](https://github.com/majd/ipatool/blob/v2.7.0/.github/workflows/release.yml) 第 48–63 行） |
| 最低系统 | **minos 27.0**（本机 `otool -l` 的 LC_BUILD_VERSION）→ **不能打包给旧系统的用户** | 编译参数是 10.15，但 go.mod 写 `go 1.25.0`，[Go 1.25 发布说明](https://go.dev/doc/go1.25)：“Go 1.25 requires macOS 12 Monterey or later”→ 实际最低 **macOS 12** |
| 架构 | arm64 单架构，30,991,090 字节 | arm64 和 amd64 分成两个 tar.gz，**没有 universal**，要自己 `lipo -create` 合并 |
| 签名 | `adhoc,linker-signed`，TeamIdentifier 未设（本机 `codesign -dvv`） | workflow 里没有 codesign 步骤；具体签名状态没有下载核实（红线） |
| 链接 | 只链接系统框架：Security、CoreFoundation、Foundation、LocalAuthentication、libresolv、libobjc（本机 `otool -L`），**没有链接 unicorn**，unicorn 运行时才下载并 dlopen | 同一份源码 |

判定：**GUI 内置官方 Release 版**（自己 lipo 成 universal，并锁定 SHA-256），不要拷贝 Homebrew 的。

### 3.4 unicorn 动态库加载与 Hardened Runtime

- 不签 Developer ID、不公证时，可以不开 Hardened Runtime。这种情况下 ad-hoc 签名的 unicorn dylib 能被 ipatool 正常 dlopen，本机 Homebrew 版的现状就是证据。
- **如果以后要公证**，Hardened Runtime 是必开的，这时内置的 ipatool 必须带上 `com.apple.security.cs.allow-jit` 和 `com.apple.security.cs.disable-library-validation`，否则 dlopen unicorn 会被拦截，表现为 SAP 登录失败。证据：AppDowngrader 的 [project.yml](https://github.com/rxliuli/AppDowngrader/blob/main/project.yml) 注释原文：“runtime symptom is SAP login failing because dlopen of Unicorn is blocked by the hardened runtime”，它对 `Resources/bin/ipatool` 执行的是 `codesign --force --options runtime --timestamp --entitlements … `。
- 二进制放在 `Contents/Resources/bin/ipatool` 或 `Contents/Helpers/`，调用时用绝对路径（`Bundle.main.url(forResource:)`）。Finder 启动的 App，PATH 里没有 `/opt/homebrew/bin`。xKleja README 列出了它要逐个探测的路径，可以佐证这一点。

### 3.5 子进程调用的几处坑

1. **登录**：交互模式下密码是用 `term.MakeRaw(stdin)` 读的，**没有 TTY 会失败**（[cmd/prompt.go](https://github.com/majd/ipatool/blob/v2.7.0/cmd/prompt.go)）。两种做法：
   - `--non-interactive -e … -p … [--auth-code …]`：简单，但**密码会出现在命令行参数里**，同一用户的其他进程用 `ps` 能看到。AppDowngrader 就是这么做的（AppStoreService.swift 第 18 行）。
   - 开伪终端（PTY），把密码写进去：xKleja 的做法，README 原文：“The password is written to a private pseudo-terminal… never placed on the command line”。推荐这种。
2. **2FA**：非交互模式下第一次调用会让 Apple 推送验证码，进程以 exit 0 结束，并输出 “2FA code is required…”。GUI 要识别这行，弹出验证码输入框，再带 `--auth-code` 重跑。
3. **进度**：见 2.4，二选一或者两个都做（a23bc 是解析文本，再用 `.tmp` 大小兜底）。
4. **账号隔离 / 不碰用户已有的 `~/.ipatool`**：可以给子进程设绝对路径的 `XDG_STATE_HOME` 加一个沙盒化的 `HOME`（a23bc 的做法）。但钥匙串槽位仍然是共享的（见 3.2）。
5. **地区**：搜索和下载都用账号所在的 storefront（本机实测中国区搜 telegram 返回 X），GUI 文案里要说明。

### 3.6 在 GitHub 分发未签名 / 未公证的 App

- **Developer ID 和公证都要付费会员**：Developer ID 证书需要 Apple Developer Program 团队的 Account Holder 才能生成（[developer.apple.com/developer-id](https://developer.apple.com/developer-id/)）；年费原文：“The Apple Developer Program annual fee is 99 USD”（[support/enrollment](https://developer.apple.com/support/enrollment/)）。
- **免费 Apple ID 能做什么**：Xcode “Personal Team” 可以在自己的设备上签名测试（[compare-memberships](https://developer.apple.com/support/compare-memberships/)：最多 10 个 App ID、3 台设备，描述文件 7 天过期）。**不能**拿到 Developer ID，**不能**公证。macOS 本地运行用 ad-hoc 签名（`codesign -s -`）就够了，不需要任何账号。本机 Homebrew ipatool 本身就是 ad-hoc 签名，运行正常。
- **用户自己这台 Mac**：在本机编译出来的 App 没有 quarantine 属性，不会被 Gatekeeper 拦。
- **别人从 GitHub 下载后**：
  - Apple 官方原文（2024-08-06，[developer news](https://developer.apple.com/news/?id=saqachfa)）：“In macOS Sequoia, users will no longer be able to Control-click to override Gatekeeper… They’ll need to visit System Settings > Privacy & Security…”。
  - 官方步骤（[support.apple.com/102445](https://support.apple.com/en-us/102445)，发布于 2026-05-27）：先尝试打开一次 → 系统设置 → 隐私与安全性 → 往下拉点“仍要打开”（Open Anyway）→ 再点“打开”，之后就记为例外。
  - 第三方说法：ad-hoc 签名、未公证的包常被报成“已损坏，无法打开”，这时界面上没有“仍要打开”，只能执行 `xattr -dr com.apple.quarantine`。a23bc、xKleja、pipa、pdx15 的 README 都这样写；[macos-tahoe.com](https://macos-tahoe.com/blog/app-is-damaged-cant-be-opened-macos-tahoe-gatekeeper-quarantine-fix-2026/) 称 Tahoe 26.5 收紧了这一点。
  - 结论：不付 99 美元，**发布页必须写清楚“系统设置 → 仍要打开”的步骤，并附 xattr 备用命令**。
- **Homebrew Cask 分发**也是一条路（AppDowngrader 用 `brew install rxliuli/tap/app-downgrader`），但它需要终端，对不用终端的用户没有帮助。

### 3.7 Sparkle 自动更新的接入成本

- 步骤（[sparkle-project.org/documentation](https://sparkle-project.org/documentation/)，文档提到当前是 Sparkle 2.9）：
  1. SPM 加入 `https://github.com/sparkle-project/Sparkle`
  2. 用 `SPUStandardUpdaterController` 加一个“检查更新”菜单项
  3. `generate_keys` 生成 EdDSA 密钥，私钥存在钥匙串里，公钥写进 Info.plist 的 `SUPublicEDKey`
  4. 在 Info.plist 写 `SUFeedURL`
  5. 每次发版用 `generate_appcast` 生成 appcast.xml 并签名，上传到 HTTPS（可以放 GitHub Release 或 GitHub Pages）
- 签名要求：发布页原文“you must cryptographically sign your updates”（EdDSA）（[publishing](https://sparkle-project.org/documentation/publishing/)）。Developer ID 只是“if possible”推荐，不是必需。文档提醒：**ad-hoc 签名又开了 Library Validation 时，Sparkle 框架会被拦**，所以不公证的版本不要开 Hardened Runtime / Library Validation。
- 成本：代码 20 行以内，加上一次性的密钥生成，加上 CI 里一步 `generate_appcast`。要注意 EdDSA 私钥的保管：私钥丢了，已经发出去的客户端就再也收不到更新。
- 风险观点：a23bc 认为“unsigned auto-update 通道是 RCE 向量”，所以只做“提示有新版”。用了 EdDSA 签名后，这个风险就降为私钥泄露的风险。
- 建议：**第一版不接 Sparkle**，只调 GitHub Releases API 检查新版本并提示用户；等装机量起来再接。

## 4. Tauri / Electron 替代路线（一句话）

**不值得**：目标只有 macOS，而同样是“包一层 ipatool”，Electron 版 a23bc 的 mac-arm64 包有 **107 MB**，SwiftUI 版 ipatoolUI 只有 **0.84 MB**（两者都来自 GitHub Release 资产页）；而且钥匙串、PTY、子进程这些难点和框架无关，换 Tauri/Electron 解决不了任何一个。只有要同时出 Windows/Linux 版时才值得考虑，而那种情况直接用现成的 a23bc（MIT）就行。
